Findings
Testing showed that the analyzer can count successful and failed login events, track failures by IP address and username, identify rapid failed login attempts, and generate a report.
The analyzer also rejected the invalid records used during testing. The empty-log test confirmed that the program can process a file containing no records without crashing.
Security Relevance
Log analysis can help security analysts identify repeated authentication failures and other activity that may require investigation. Validating input helps prevent malformed records from being incorrectly counted as legitimate events.
Alerts do not prove that an attack occurred. Analysts should review additional evidence before deciding whether activity is malicious.
Limitations
This is a beginner project using fictional sample logs. Its detection thresholds are configurable examples and have not been validated for a production environment. It does not provide real-time monitoring or confirm whether an account or system was compromised.
Conclusion
Phase 9 testing verified the expected behavior of the analyzer across normal, invalid, suspicious, and empty-log scenarios. The project demonstrates foundational Python programming, log analysis, input validation, threshold-based detection, and security reporting.
